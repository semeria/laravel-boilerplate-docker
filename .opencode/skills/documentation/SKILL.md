# Documentación del proyecto

- Lee `AGENTS.md` y únicamente el documento que corresponda al cambio; no cargues todo `/docs`.
- Usa como fuente el código y la configuración actuales. No conviertas suposiciones o propuestas futuras en hechos; marca lo desconocido como `Pendiente de documentar`.
- Actualiza solo el documento afectado y conserva su formato existente: resumen inicial, índice, Markdown conciso y contenido autónomo.
- Selecciona el documento canónico por tema: `project.md`, `architecture.md`, `auth.md`, `database.md`, `api.md`, `ui.md`, `deployment.md`, `roadmap.md` o `decisions.md`.
- Evita repetir información que ya tenga un documento; enlaza al documento pertinente cuando sea suficiente.
- No traslades documentación técnica extensa a `AGENTS.md`; mantenlo limitado a reglas globales y referencias esenciales.
